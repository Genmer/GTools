# GTools 任务清单（需求拆解版）

> 依据：用户口述需求基线（2026-09-23）。本文只做需求拆解与验收定义，不做技术选型、不替用户拍板需求。
> 已定决策不重新讨论：Electron；macOS + Windows（开发机 macOS Intel x64）；全局快捷键唤起 → 无边框居中搜索窗 → 失焦隐藏 → 拼音/英文模糊搜索 → 关键字路由进插件；插件化（内置随包打包，外部插件协议预留）；MVP 内置插件 4 个；主题白/黑/玻璃可切换；设置可改快捷键与主题。
>
> **明确不做（范围外，防止蔓延）**：插件市场、账号体系、云同步、超级面板（划词）、悬浮球、AI 生成插件、自动更新、本期的外部插件动态加载与安全沙箱。

## 一、专项分析：插件协议在需求层面必须满足什么

用户的强诉求有两句话，各推导出一组协议硬性需求：

> 「内置插件与外部插件走**同一套机制**」 → A 组
> 「每个插件可**独立开发互不干扰**」 → B 组

### A 组：同一套机制（内置插件不得有任何特权旁路）

| # | 需求 | 含义 | 可验收判据 |
|---|------|------|-----------|
| A1 | **唯一插件契约** | 插件 = 清单（声明）+ 实现（功能）。宿主只通过契约识别、加载、驱动插件；不存在"只有内置才能走"的专用通道 | 4 个内置插件全部按契约实现，宿主代码中检索不到任何针对具体插件的硬编码分支 |
| A2 | **声明式路由** | "输入某关键字 → 进入某插件"的路由表完全来自各插件清单的声明，宿主不内置任何插件的关键字 | 新增一个空壳示例插件（只添加清单+实现文件、不改宿主代码），用其关键字即可唤起；从磁盘移除任一内置插件目录，宿主正常启动且该关键字消失，其余插件可用 |
| A3 | **宿主能力 API 化** | 插件需要的一切宿主能力（读写剪贴板、按插件隔离的存储、通知、网络请求、打开应用/文件、窗口控制）都经统一的宿主 API 面暴露，版本受控；内部插件同样只许用这套 API，不得 import 宿主私有模块 | 静态依赖检查：插件目录内不出现对宿主内部模块路径的引用；宿主 API 有版本号 |
| A4 | **协议版本化** | 清单携带协议版本号，宿主加载前校验兼容性，不兼容则拒绝并给出用户可读提示 | 用错误版本号的清单测试：被拒绝加载且有提示，宿主不崩溃 |

### B 组：独立开发互不干扰

| # | 需求 | 含义 | 可验收判据 |
|---|------|------|-----------|
| B1 | **全局唯一 ID + 命名空间隔离** | 插件 ID 全局唯一；持久化存储按键空间按插件 ID 隔离，A 插件在协议层面读不到 B 插件的数据 | 集成测试：两个插件各写各自存储，互相不可见；ID 冲突时宿主拒绝加载后者并提示 |
| B2 | **错误隔离** | 单个插件抛错/崩溃只影响该插件自身视图，宿主外壳与兄弟插件不受影响 | 人为让某插件抛异常：外壳仍可搜索、可进其他插件；出错位置显示降级提示而非白屏 |
| B3 | **生命周期可管理** | 宿主可启用/禁用插件，禁用即时生效（从路由消失、常驻进程停止），重新启用可恢复 | 禁用"剪贴板历史"→ 后台记录停止、关键字消失、其余插件不受影响；重新启用后恢复记录 |
| B4 | **两种激活模型** | 清单能表达：①触发式（关键字进入时才实例化，如开发者工具集）；②常驻式（应用启动即后台运行，如剪贴板历史） | 剪贴板历史以常驻式声明并在未唤起时仍能记录；开发者工具集以触发式声明且未唤起时不占运行资源 |
| B5 | **UI 边界** | 插件 UI 限定在宿主给定的视图容器内，不能修改搜索框、窗口行为、主题等外壳元素 | 任一插件的 UI 无法遮挡/替换搜索框，无法改变窗口显隐行为 |
| B6 | **零共享状态** | 插件之间唯一交集是宿主 API；因此 4 个内置插件可由不同人/不同会话并行开发，集成时无冲突面 | 代码结构上插件目录两两之间无 import；4 插件开发任务（T3.1–T3.4）可并行派发互不等待 |

### C 组：本期预留、本期不做（外部插件）

协议字段设计时**不得含有"只有随应用打包才能满足"的假设**（如：加载来源、安装路径字段本期即可预留、留默认值），但动态加载外部包、安全沙箱、权限授予 UI、签名校验均明确后置，不做实现。空壳示例插件（A2 判据）用于证明外部路径未被堵死，即本期外部插件的验收终点。

## 三、分阶段任务明细

### 阶段 0：工程脚手架

**T0.1 Electron 工程初始化**（MVP，依赖：无）
- 内容：可运行的主进程 + 渲染进程空窗口工程，dev 启动命令写入 README。
- 验收：
  1. macOS 上按 README 的启动命令运行，拉起一个空白窗口，无报错；
  2. 命令行退出进程后无残留 Node/Electron 进程（`ps aux | grep -i electron` 为空）。

**T0.2 项目规范与目录规约**（MVP，依赖：T0.1）
- 内容：确立"宿主代码"与"插件目录"物理分离的目录结构，写明插件开发规约入口（对应协议 A1/A3/B6 的物理前提）；沉淀为项目 AGENTS.md，供后续每个插件的独立开发会话自动加载。
- 验收：
  1. 仓库中宿主代码与各插件代码分属不同顶层目录，插件目录两两之间无 import；
  2. 项目 AGENTS.md 存在且含目录约定、插件开发规约、注释与提交纪律的引用。

**T0.3 打包流水线**（MVP，依赖：T0.1）
- 内容：macOS 可打包出 .app 与 .dmg；Windows 打包配置就绪（可暂无环境实测）。
- 验收：
  1. 一条打包命令产出 macOS .app，双击可运行，全局快捷键可用；
  2. Windows 打包配置存在于工程中且配置校验通过（实际出包与运行验证归 T4.1）。

### 阶段 1：宿主外壳（MVP 核心）

**T1.1 全局快捷键唤起/隐藏**（MVP，依赖：T0.1）
- 内容：应用在后台常驻（Dock/任务栏可无图标），任意时刻按全局快捷键切换显示/隐藏搜索窗。默认键值见开放点 2，设置页可改（联动 T2.2）。
- 验收：
  1. 聚焦任意其他应用时按快捷键，搜索窗 300ms 内出现（指标建议值，最终数值随 T4.2 确认）；
  2. 窗口已显示时再按快捷键，窗口隐藏；
  3. 快捷键被其他应用占用时有用户可读的冲突提示，应用不崩溃；
  4. 应用重启后快捷键仍生效（无需重新登录系统）。

**T1.2 无边框居中搜索窗 + 失焦自动隐藏**（MVP，依赖：T0.1；与 T1.1 并行）
- 内容：无边框窗口，屏幕水平居中；出现时搜索框自动聚焦；失焦（点击窗口外/切换应用）自动隐藏。隐藏为不可见而非销毁，保证再次唤起瞬时。
- 验收：
  1. 唤起后不做任何输入直接切到别的应用，窗口在 500ms 内隐藏；
  2. 窗口位置水平居中（误差 ≤ 8px），再次唤起位置不变；
  3. 隐藏后再次唤起 ≤ 300ms 出现且输入光标已在搜索框内；
  4. 在窗口内点击（如拖动、选中文本）不触发隐藏。

**T1.3 拼音/英文模糊搜索匹配**（MVP，依赖：T1.2）
- 内容：对"插件及其功能项"两个层级做模糊匹配：英文子串、中文子串、拼音全拼、拼音首字母。此为纯匹配逻辑，先用固定测试数据驱动，后接真实插件清单。
- 验收（单元测试用固定词条驱动，例：词条「JSON 格式化」）：
  1. 输入 `json` 命中；输入 `格式化` 命中；输入 `geshi` 命中；输入 `gsrh` 命中；
  2. 输入 `kfz`（开发者）能命中「开发者工具」类词条；
  3. 无命中时不展示空列表，显示无结果占位；
  4. 键入到结果刷新 ≤ 100ms（100 词条规模，建议值）。

**T1.4 插件协议 v1**（MVP，依赖：T0.2；本任务是架构性任务，先行于所有插件）
- 内容：定义第一节的 A1–A4、B1–B6 全部条款：清单（ID、名称、图标、版本、协议版本、触发关键字、激活模型、加载来源预留字段）、生命周期（加载/启用/禁用/卸载）、宿主 API 面（剪贴板、隔离存储、通知、网络、打开应用、窗口控制）。产出协议文档 + 空壳示例插件。
- 验收：即第一节各表的可验收判据，逐条执行：
  1. A2：空壳示例插件不改宿主代码即可被其关键字唤起；移除任一内置插件目录宿主仍正常启动；
  2. A4：错误协议版本的清单被拒绝加载且有提示；
  3. B1：两插件存储互不可见；ID 冲突被拒；
  4. B2：人为抛错的插件不影响宿主与其他插件，出错处显示降级提示；
  5. B4：清单能声明触发式与常驻式两种激活模型（各有一个插件或测试桩实例化验证）。

**T1.5 关键字路由 + 插件视图容器**（MVP，依赖：T1.3、T1.4）
- 内容：搜索框输入命中某插件关键字后进入该插件视图（宿主提供容器，B5 边界）；Esc/清空关键字退回全局搜索。
- 验收：
  1. 输入插件关键字 + 空格进入该插件视图，视图内搜索框变为插件上下文；
  2. Esc 逐级退出：先退回全局搜索，再隐藏窗口；
  3. 插件视图无法遮挡搜索框、无法改变窗口显隐（B5）；
  4. 进入插件后其内容由该插件独立提供（路由层不含插件业务逻辑）。

**T1.6 插件启用/禁用管理**（MVP，依赖：T1.5）
- 内容：宿主维护插件启用状态（界面形态从简，如设置内列表），禁用即时生效。
- 验收：
  1. 禁用任一插件：其关键字立即从路由消失、常驻任务停止（B3）；
  2. 重新启用后无需重启应用即恢复；
  3. 禁用状态重启应用后保持（持久化）。

### 阶段 2：设置与主题（MVP）

**T2.1 主题系统（白/黑/透明玻璃）**（MVP，依赖：T1.2）
- 内容：三主题：白（默认）、黑、透明玻璃（macOS vibrancy / Windows 亚克力）；全部 UI 以主题变量驱动。默认白为已定决策。
- 验收：
  1. 三主题任意切换即时生效，重启后保持所选主题；
  2. 玻璃主题下窗口背景呈现系统原生透明效果（macOS 开发机上目测验证；Windows 亚克力归 T4.1）；
  3. 任一主题下文字对比度可读（黑主题无深底深字、白主题无白底白字）；
  4. 内置插件 UI 颜色全部取自主题变量：切换主题时 4 个插件视图同步变化（依赖插件完成，最终回归在 M3）。

**T2.2 设置页：修改全局快捷键**（MVP，依赖：T1.1）
- 内容：设置页可录入新快捷键并即时生效，含冲突检测。
- 验收：
  1. 录入新组合键并保存后，新键唤起、旧键失效，无需重启应用；
  2. 录入与系统/常见应用冲突的组合（如 ⌘C）时被拒绝并提示；
  3. 重启应用后新快捷键仍生效；
  4. 设置页含主题切换入口（与 T2.1 联动验收）。

### 阶段 3：内置插件 ×4（MVP，互相独立可并行，均依赖 T1.5）

**T3.1 开发者工具集**（触发式插件；依赖 T1.5；进入关键字见插件清单，MVP 至少覆盖以下 7 个子工具）

| 子工具 | 验收标准 |
|--------|---------|
| JSON 格式化/校验 | 粘贴合法 JSON → 一键格式化（缩进可调 2/4 空格）与压缩；非法 JSON → 指出首个错误的位置（行/列或字符序号）；结果可一键复制 |
| 时间戳互转 | 输入秒/毫秒时间戳 → 显示本地时区可读时间；输入可读时间 → 输出秒+毫秒两种时间戳；视图常显"当前时间戳"并每秒刷新 |
| UUID | 生成 v4；一键复制；支持一次批量生成（条数可输入） |
| Base64 | 加密/解密双向；UTF-8 中文双向正确（`你好` ↔ `5L2g5aW9`）；非法 Base64 输入解码时报错不崩溃 |
| 正则测试 | 输入 pattern、flags、测试文本 → 实时列出全部匹配（含分组捕获）；非法正则提示语法错误位置 |
| 颜色转换 | HEX ↔ RGB ↔ HSL 三向互转；输入任一格式实时显示另两种；非法颜色值提示 |
| JWT 解码 | 粘贴 JWT → 分段显示 header、payload 的可读 JSON；过期时间字段额外换算为可读时间并标注是否已过期；注意：仅解码不验签（如需验签属新增需求，见开放点 6） |

- 整体验收：7 个子工具均可从插件内导航进入；全部子工具在黑/白/玻璃三主题下可读（回归 T2.1 判据 4）；本插件不 import 任何其他插件与宿主私有模块（A3）。

**T3.2 翻译**（触发式插件；依赖 T1.5；**外部前置条件：翻译 API 供应商与密钥由用户提供，见开放点 1**）
- 内容：输入文本翻译（中英为主，方向自动检测或手动切换）；支持一键读取剪贴板内容作为输入源；结果一键复制。
- 验收：
  1. 输入中文 → 出英文译文；输入英文 → 出中文译文（方向自动检测或手动切换，二者至少其一可用）；
  2. 复制任意文本后进入翻译插件，一键"读剪贴板"填入输入框；
  3. 译文可一键复制，粘贴到其他应用内容一致；
  4. API 请求失败（断网/密钥无效）时显示用户可读错误，不崩溃、不影响其他插件（B2 交叉验证）；
  5. API 密钥不硬编码在代码中（本地配置读取）。

**T3.3 剪贴板历史**（**常驻式插件**，协议 B4 的第一个真实实例；依赖 T1.5、T1.6）
- 内容：应用启动即在后台监听剪贴板，记录文本与图片；列表倒序展示、可搜索、点击回贴到剪贴板；可清空。
- 验收：
  1. 未唤起窗口时复制文本 A、再复制图片 B，进入插件后列表倒序展示 B、A 两条，含复制时间；
  2. 连续复制相同内容只保留最新一条（去重）；
  3. 搜索框输入关键词可过滤历史（复用 T1.3 匹配能力）；
  4. 点击文本条目 → 该内容回到剪贴板，在其他应用粘贴得到一致内容；图片条目同样可回贴；
  5. 禁用本插件（T1.6）后后台监听立即停止、不再产生新记录；重新启用恢复（B3 判据）；
  6. 历史持久化：重启应用后记录仍在；容量上限默认值可配置（数值见开放点 3）。

**T3.4 应用启动器**（触发式插件；依赖 T1.5）
- 内容：扫描本机已安装应用（macOS：/Applications 及子目录的 .app；Windows：开始菜单快捷方式目录），拼音/英文模糊搜索，回车启动。
- 验收：
  1. 首次打开能列出 ≥ 数十款已装应用（含名称与图标），扫描在后台进行不阻塞界面；
  2. 输入 `wechat` 命中微信（若装）；输入 `wx` 或 `weixin` 拼音也命中（复用 T1.3）；
  3. 回车启动所选应用，搜索窗隐藏；
  4. 二次唤起秒出列表（扫描结果缓存）；新装应用后在缓存刷新策略内出现（手动刷新入口或定时刷新，实现从简，需可触发）；
  5. Windows 开始菜单扫描逻辑在本任务实现，实际验证归 T4.1。

### 阶段 4：跨平台与发布

**T4.1 Windows 平台适配验证**（⚠️ 依赖 Windows 实机环境，见开放点 4；在此之前所有任务不得引入"仅 macOS 可行"的架构假设）
- 验收：
  1. Windows 上：快捷键唤起、失焦隐藏、搜索路由、三主题（含亚克力）全部按 T1.x/T2.1 判据复测通过；
  2. 应用启动器列出开始菜单应用并可启动；
  3. T0.3 的 Windows 打包产物可安装运行。

**T4.2 性能验收**（MVP 基础指标；指标数值为建议值，最终以用户确认为准，见开放点 5）
- 验收：
  1. 快捷键到窗口可见 ≤ 300ms；
  2. 键入到搜索结果刷新 ≤ 100ms（清单规模）；
  3. 后台常驻内存占用记录基准值并评估（给出数字即可，不设硬门槛）；
  4. 连续唤起/隐藏 50 次无内存持续增长（泄漏冒烟）。

**T4.3 macOS 打包分发**（依赖 T0.3、M3）
- 验收：分发包在**另一台未装开发环境的 macOS** 上安装后，全部 MVP 验收项（T1.x、T2.x、T3.x）通过一遍冒烟。

**T4.4 外部插件动态加载**（❌ 明确后置，本期非目标，仅在此登记以防遗忘）
- 触发条件：用户提出要单独开发外部插件时启动；届时基于 T1.4 的协议版本机制扩展。

## 五、待用户确认的开放点（不替用户拍板）

1. **翻译 API 供应商与密钥**：选哪家、是否有预算/免费额度、密钥如何本地配置？——T3.2 的实现前置条件。
2. **默认全局快捷键键值**：建议给一个不与系统冲突的默认值（如 ⌥Space 类），由用户确认。
3. **剪贴板历史细节**：容量上限默认值（建议 500 条）、图片是否记录（占空间大）、退出时是否清空历史（隐私选项）。
4. **Windows 验收环境**：是否有可用的 Windows 实机/虚拟机？决定 T4.1 排期（不影响 M1–M3）。
5. **性能指标数值**：本文所有 300ms/100ms 为建议值，需用户确认或调整。
6. **JWT 是否需要验签**：现按"仅解码"拆解；验签需要密钥/公钥来源，属新增需求，需用户拍板。
